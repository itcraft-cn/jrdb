## 一、项目概述

### 1.1 模块结构

```
jrdb/
├── jrdb-jdbc/                 # 同步 JDBC 实现（核心模块，55 源文件）
│   ├── memory/                # 堆外内存管理 (MemoryPool, SlotAllocator, Unsafe)
│   ├── storage/               # 存储格式 (RowStore 行存/ColumnStore 列存)
│   ├── mapping/               # ASM 实体映射 (MapperRegistry, EntityMapper)
│   ├── session/               # 会话管理 (Session, SessionFactory)
│   ├── cache/                 # 缓存 (L1 Statement/L2 Result)
│   ├── sql/                   # SQL DSL (SqlDsl, SqlTemplate)
│   ├── type/                  # 类型处理器 (TypeHandlerRegistry)
│   └── transaction/           # 事务管理
├── jrdb-r2dbc/                # 响应式 R2DBC 实现（10 源文件）
├── jrdb-spring-boot-starter/  # Spring Boot 自动配置（14 源文件）
└── jrdb-test/                 # 单元测试 + JMH 基准测试
```

### 1.2 核心设计

| 特性 | 实现方式 |
|------|----------|
| 内存模型 | 堆外内存 (Unsafe.allocateMemory) |
| 映射方式 | ASM 动态字节码生成 |
| 缓存级别 | L1(Statement) + L2(结果缓存) |
| 存储格式 | RowStore(行存) / ColumnStore(列存) |

## 二、做得好的部分（表扬）

### 2.1 架构设计优秀

1. **模块职责清晰**
   - `memory` 包专注堆外内存管理，`storage` 包专注数据存储格式，`mapping` 包专注实体映射
   - 各包之间依赖关系清晰，符合单一职责原则

2. **接口设计合理**
   - `Session` 接口定义了清晰的会话边界
   - `EntityMapper<T>` 接口定义了映射器标准
   - `TypeHandler<T>` 接口支持类型处理器扩展

3. **策略模式应用**
   - `QueryAction` 函数式接口根据缓存级别选择查询策略
   - `OverflowHandler` 支持多种溢出处理策略

### 2.2 性能优化到位

1. **堆外内存管理优秀** (`MemoryPool.java`, `SlotAllocator.java`)
   - 预分配内存池，避免运行时分配开销
   - 位图管理槽位，高效分配/释放
   - 提供 `Fast` 方法跳过边界检查，追求极致性能

2. **ASM 字节码生成** (`MapperClassGenerator.java`)
   - 动态生成映射代码，避免反射开销
   - JVM 可内联优化生成的字节码
   - 支持基本类型和包装类型的不同处理

3. **多级缓存设计** (`SessionImpl.java`)
   - L1 缓存：PreparedStatement + QueryMeta
   - L2 缓存：查询结果（Guava Cache）
   - 缓存失效机制完善（更新后清空缓存）

### 2.3 线程安全考虑

1. **ThreadLocal 使用正确** (`SessionImpl.java:162`)
   ```java
   private final ThreadLocal<byte[]> rowBuffer;
   // 使用 ThreadLocal.withInitial() 初始化，避免内存泄漏
   ```

2. **ConcurrentHashMap 使用** (`MapperRegistry.java:26-27`)
   ```java
   private final Map<Class<?>, EntityMapper<?>> mapperCache = new ConcurrentHashMap<>();
   private final Map<Class<?>, MappingConfig> configCache = new ConcurrentHashMap<>();
   ```

3. **volatile 状态标志** (`MemoryPool.java:61`, `SessionFactory.java:47`)
   ```java
   private volatile boolean destroyed;
   private volatile boolean closed;
   ```

4. **synchronized 方法保证并发安全** (`SlotAllocator.java`, `MemoryPool.java`)
   - 分配/释放方法均使用 synchronized 修饰

### 2.4 代码规范优秀

1. **JavaDoc 详尽** - 几乎所有公共方法都有完整的 JavaDoc
2. **常量化** - 魔幻数值基本都定义为常量
3. **异常处理** - 使用描述性异常消息，包含参数名

## 三、发现的问题（需要改进）

### 3.1 线程安全问题（P0 - 必须修正）

#### 问题 1：`JrdbTransactionManager` 中的 ThreadLocal 内存泄漏风险

**文件**: `jrdb-spring-boot-starter/src/main/java/cn/itcraft/jrdb/springboot/transaction/JrdbTransactionManager.java`

**问题描述**:
```java
private final ThreadLocal<Connection> connectionHolder = new ThreadLocal<>();

@Override
public TransactionStatus getTransaction(TransactionDefinition definition) throws TransactionException {
    Connection conn = dataSource.getConnection();
    conn.setAutoCommit(false);
    connectionHolder.set(conn);  // ⚠️ 只 set，未确保 remove
    return new JrdbTransactionStatus(conn);
}
```

**风险**:
- 线程池场景下，线程复用导致 `connectionHolder` 中的 Connection 未被清理
- 长时间运行后可能导致 Connection 泄漏
- 异常情况下可能未调用 `closeConnection()`

**建议修复**:
```java
// 使用 try-finally 确保 ThreadLocal 清理
private void closeConnection() {
    Connection conn = connectionHolder.get();
    if (conn != null) {
        try {
            conn.setAutoCommit(true);
            conn.close();
        } catch (SQLException e) {
            // 记录日志
        } finally {
            connectionHolder.remove();  // ✅ 确保 remove
        }
    }
}
```

#### 问题 2：`R2dbcExecutor` 中 Connection 未正确关闭

**文件**: `jrdb-r2dbc/src/main/java/cn/itcraft/jrdb/r2dbc/executor/R2dbcExecutor.java`

**问题描述**:
```java
private void closeConnection(Connection conn) {
    Mono.from(conn.close()).subscribe();  // ⚠️ 订阅后未处理异常
}
```

**风险**:
- 关闭 Connection 时发生异常会被忽略
- Reactor 流未正确订阅可能导致资源泄漏

**建议修复**:
```java
private void closeConnection(Connection conn) {
    Mono.from(conn.close())
        .doOnError(e -> log.warn("关闭连接失败", e))
        .subscribe();
}
```

#### 问题 3：`QueryResultCache` 的 key 构建可能存在哈希冲突

**文件**: `jrdb-jdbc/src/main/java/cn/itcraft/jrdb/jdbc/cache/QueryResultCache.java`

**问题描述**:
```java
private String buildKey(String sql, Object[] params) {
    if (params == null || params.length == 0) {
        return sql;
    }
    return new StringBuilder(sql.length() + 12).append(sql).append(':')
        .append(Arrays.hashCode(params)).toString();  // ⚠️ 仅用 hashCode 作为区分
}
```

**风险**:
- `Arrays.hashCode()` 可能产生冲突，不同参数产生相同哈希值
- 极端情况下会导致缓存命中错误数据

**建议修复**:
```java
private String buildKey(String sql, Object[] params) {
    if (params == null || params.length == 0) {
        return sql;
    }
    // 使用完整参数内容作为 key 的一部分
    return new StringBuilder(sql).append(':')
        .append(Arrays.deepToString(params)).toString();
}
```

### 3.2 事务使用问题（P1 - 应当修正）

#### 问题 4：`TransactionManager` 的事务传播未处理

**文件**: `jrdb-jdbc/src/main/java/cn/itcraft/jrdb/jdbc/transaction/TransactionManager.java`

**问题描述**:
```java
public <T> T executeInTransaction(Function<Transaction, T> function) throws SQLException {
    Transaction tx = beginTransaction();
    try {
        T result = function.apply(tx);
        tx.commit();
        return result;
    } catch (Exception e) {
        tx.rollback();  // ⚠️ 如果 function 内又开启事务，会导致嵌套事务问题
        ...
    }
}
```

**风险**:
- 不支持事务传播（REQUIRED/REQUIRES_NEW 等）
- 如果 function 内部再次调用 `executeInTransaction`，会产生嵌套事务

**建议**:
- 添加事务传播机制支持
- 使用 ThreadLocal 跟踪当前事务状态

### 3.3 代码结构问题（P1 - 应当修正）

        return result.getLong(colName);  // ⚠️ 用异常控制流程
